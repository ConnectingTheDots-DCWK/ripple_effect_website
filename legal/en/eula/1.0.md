## 7. What the application sends, and when

**From version 1.6, the application makes no network request of any kind until
you have accepted this Agreement.** There is no exception to that — not for
updates, not for diagnostics, not for anything else. Nothing is sent before
you have agreed that anything may be. A build earlier than 1.6 does not ask
for acceptance and makes the update check described in item 1 below on first
launch; that is the only request it makes unasked, and it carries nothing
about you.

Once you have accepted, these are the only things that leave your machine:

1. **An update check**, once per launch: a request to `ripplefx.app` asking
   what the current release is. It carries no identifier, no version and no
   information about you, and the comparison happens on your machine.
2. **A list of contributors**, when you open the About box: a request to
   `ripplefx.app` for the people credited in the support repository, which
   the site answers from GitHub itself. Versions before 1.5 asked GitHub's
   public API directly.
3. **A crash report, and only if you say so.** After a crash, the next launch
   asks whether to send the report it saved, names every file in it and says
   what each one contains. Nothing is sent unless you answer yes to that
   report, there is no setting that answers in advance, and declining is
   final for that report. Before asking, the application checks that the
   server it would send to can be reached, with a request that carries
   nothing about you.
4. **Usage statistics, and only if you switch them on.** From the version
   that introduces them, the application asks once whether to send them,
   with the complete list of what would be sent in front of the question and
   neither answer preselected. Nothing is sent unless you say yes, the
   setting can be switched off at any time, and switching it off stops them
   at once. No content you author is ever included.
5. **Engine fixes, unless you switch them off.** From version 1.5, once per
   launch, a request to `ripplefx.app` asking whether a fix exists for the
   engine the application is running, carrying that engine's version, its
   milestone, the platform and an identifier of the interface between the
   application and its engine, and nothing about you. A fix that exists is
   downloaded, checked against our signature and used from the next launch.
   It never changes what the Software can do. *Engine updates*, under
   *Settings ▸ Updates*, switches both requests off.
6. **What the Service needs, if you sign in.** Signing in, and anything you
   then do with the hosted features, goes to our servers under the [Terms of
   Service](/terms/). Nothing is sent for the Service before you sign in.
7. **Whatever you send yourself.** Version control pushes to a repository you
   configured, with credentials you supplied, held in your operating system's
   credential store. Opening documentation or a support page hands a URL to
   your browser — from version 1.5 through a redirect on `ripplefx.app`, which
   sees that request and nothing else. We are not a party to anything beyond
   it.

The Software keeps a session log on your machine. It is not transmitted, there
is no uploader for it, and it is deleted automatically when a session ended
without anything going wrong.

What each of those involves, what a crash report contains and how long
anything is kept is in the [Privacy Notice](/privacy/), which forms part of
this Agreement.

**Nothing you author is sent anywhere by the application.** Your passages,
boards, projects, scripts and exports stay on your machine unless you move
them yourself or, separately and by signing in, you choose to use the Service.
