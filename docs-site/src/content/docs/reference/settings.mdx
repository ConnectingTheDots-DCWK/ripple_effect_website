The gear in the app bar, on every screen, opens the Settings dialog. Settings belong to the app, not to a project, so they follow you from project to project.

Every option is a choice among a few named things, drawn as a segmented control with the current choice lit, and a line under the control says what that choice means. A choice takes effect when pressed; there is no Apply. The exception to the segmented control is *Language*, a drop-down.

The app bar keeps only what has news: an available update, the agents mark while an assistant is connected or could not reach the app, and the permissions indicator while something is using the microphone, the location or the date and time, one glyph per kind in use. Hovering the indicator, or reaching it with the keyboard, says what is using each kind; pressing it opens the [Permissions](#permissions) page. The home page's bar also has the News button, with a count while something is unread; see [News](#news).

## Pages

The dialog has seven pages down a rail on its left. Every page has the same height, and both columns scroll.

| Page | Rail description | Holds |
| --- | --- | --- |
| *General* | Appearance, accessibility, language | How the app looks, reads and plays |
| *Data control* | What leaves this machine | *Usage statistics* |
| *Permissions* | What this app may use here | *Microphone*, *Location*, *Date and time*, and a stand-in for the last two; see [Permissions](#permissions) |
| *Updates* | Channel, release notes, engine fixes, news | *Release channel*, *Release notes* and its filters, *Engine updates*, *Use the bundled engine*, *News* |
| *Agents* | Assistants that reach the app | The assistant connection; see [MCP tools](/reference/mcp-tools/) |
| *Support* | Questions, bugs, ideas | [The Support page](#support-page) |
| *About* | Version, credits, licences | The About box |

*Agents*, *Support* and *About* are pages of the dialog rather than settings. The command palette's *Agents*, *Support* and *About* commands open their pages, and so does the agents mark in the app bar.

*Documentation* leads the pointers in the About box. Panels that explain a feature (the variables panel, the agents page, the Python sandbox, the export dialog, the metadata editor and the state machine editor's bar) say what you are looking at and link to the documentation page that carries the rest.

## General

Rows in page order.

| Row | Choices | Meaning |
| --- | --- | --- |
| *Language* | *System*, then each available language under its own name | The language of the app's own menus, dialogs, messages and tips |
| *Appearance* | *System*, *Light*, *Dark* | *System* follows the operating system; the others are always that theme |
| *Links* | *Curved*, *Right-angled* | How wires are drawn on a board |
| *Contrast* | *Standard*, *More* | How firmly text and controls separate; see [Contrast](#contrast) |
| *Colour vision* | *Off*, *Protan*, *Deutan*, *Tritan* | Which palettes are swapped; see [Colour vision](#colour-vision) |
| *Playing* | *128*, *512*, *2,048*, *8,192*, *None* | The loop ceiling |
| *Countdowns* | *As written*, *Ten times longer*, *Off* | How long you are given when a passage counts down to a choice |
| *Writing* | *Check spelling and grammar*, *Off* | Whether English passages and notes are checked as you type; see [How to check spelling and grammar](/how-to/check-spelling-and-grammar/) |
| *Dictation* | *Off*, *On* | Whether a microphone floats over the passage and note editors; see [Dictation](#dictation) |

### Language

- Each language is listed under its own name, so a language is findable when the app is showing one that cannot be read.
- *System* follows the operating system's language and says which language it currently resolves to.
- The setting is the language of the app only. A project's own text and languages are set in the project's settings; see [Passages, choices, languages and reading time](/reference/passages/).
- The row is shown only in a build that ships more than one language.
- A stored language this build does not offer is read as *System*.
- Italian is currently the only language besides English. It was drafted by a model and spot-checked rather than read line by line, so report anything that reads oddly.

### Appearance

*System* follows whatever the OS is set to. *Light* and *Dark* are always that theme. Appearance is independent of Contrast and Colour vision, so dark and *More* contrast can be on together.

The default look is warm: a paper-toned light mode, a lamp-lit charcoal dark mode, and one ember accent for focus, selection and the main action on each screen. Node families, traced routes, version-control marks and tags take earthier colours to match. Links in Markdown are underlined, and the app icon is ember, matching the mark in the app bar.

The app ships three typefaces of its own, so it looks the same on every machine: Instrument Sans for menus, panels and buttons, Literata for passages and notes (as you write them, on a board and while a campaign plays), and JetBrains Mono for code. Passages are larger and more open in the editor, and larger again while a campaign plays, in a column narrow enough to read comfortably however wide the window is.

### Links

| Choice | Wires |
| --- | --- |
| *Curved* | Curve from port to port. Double-click a wire to add a handle and drag it to route the wire. |
| *Right-angled* | Run in straight legs and turn at right angles. A handle is a corner; dragged, it lines up with its neighbours. |

### Playing

*Playing* is the loop ceiling: how many times one loop node may go round before a campaign stops with an error and offers you the node. It is counted per loop and per board; jumping away and coming back starts the count again.

| Choice | Behaviour |
| --- | --- |
| *128*, *512*, *2,048*, *8,192* | The campaign stops with an error at that count |
| *None* | A loop node may go round for ever; a *While* with nothing breaking out of it never ends and does not stop the campaign |

*Countdowns*, under it, is how long you are given when a passage counts down to a choice. It is your setting rather than the story's, so every countdown you play is under it, and it is there for a reader who needs more time.

| Choice | Behaviour |
| --- | --- |
| *As written* | Countdowns run for the time the author set |
| *Ten times longer* | Every countdown, and the wait before it, lasts ten times as long |
| *Off* | No countdown runs; the story waits for you to choose |

### Dictation

A section under *Writing*. Dictation is *Off* until you switch it on.

| Row | Choices | Meaning |
| --- | --- | --- |
| *Dictation* | *Off*, *On* | *Off*: no microphone in the editors. *On*: a microphone floats over the passage and note editors; press it, speak, and your words are typed at the cursor. Everything is heard on this computer; nothing you say leaves it. |
| *Listens with* | *English*, *Multilingual* | *English* is the most accurate for English, and English only. *Multilingual* hears 32 languages, and is told the language of the passage you are writing in; a note is in the project's default language. |

Under them is a row per model, *English* and *Multilingual*:

| Part | Shows |
| --- | --- |
| Status | *Not downloaded*, *Part-way* with how much has arrived, *Downloading* while it comes, or *Downloaded*, each with the model's size |
| *Licence* | The licence NVIDIA publishes the model under, linked: the NVIDIA Open Model License for *English*, the OpenMDW License 1.1 for *Multilingual* |
| **Download** / **Resume** | Fetches the model once: about 2.3 GB (English) or 2.4 GB (Multilingual). **Resume** carries on a download that was interrupted or stopped. |
| Progress bar and **Stop** | While the model downloads |
| Bin, *Delete from this computer* | Removes a downloaded or part-way model and gives the space back |

Downloading the model that is not chosen, while the chosen one is not on disk, makes it the chosen one. A download that fails says why under the row: not enough free space, the download could not be reached or was refused, a file arrived damaged and was thrown away, or the model could not be written to disk. Switching dictation off frees the model loaded in memory; the files stay on disk. The request a download makes is in [What the app sends](/about/what-the-app-sends/#requests-you-cause), and using the model is [How to dictate a passage or a note](/how-to/dictate-a-passage/).

## Contrast

| Choice | Effect |
| --- | --- |
| *Standard* | Text and controls clear the usual accessibility floor. |
| *More* | Body and caption text reach the stricter accessibility grade (AAA). Every text field, button, chip, switch and checkbox has a findable edge. Muted text, control edges and hairlines are firmer. |

Colours stay the same and the page does not change shape.

## Colour vision

| Choice | Palettes recoloured for |
| --- | --- |
| *Off* | The house colours |
| *Protan* | Protanopia and protanomaly |
| *Deutan* | Deuteranopia and deuteranomaly, the commonest kind |
| *Tritan* | Tritanopia and tritanomaly |

A mode recolours everything the app uses colour to tell apart:

- the node families on a board;
- traced routes;
- the marks version control puts on files;
- status colours;
- syntax highlighting;
- the diff, which stops being red and green.

Palettes are chosen so that things which share a shape do not share a colour, and are checked against a simulation of all eight kinds of colour blindness. Neutral greys are not changed.

### Limits

- Three places tell categories apart by hue and nothing else: the board minimap and the overview's, where a family is a few-pixel rectangle with no icon or label; the traced routes; and a soundscape clip too narrow to have its mode written on it. A colour-vision mode improves them without making them readable to everyone.
- There is no mode for either achromatic kind of colour blindness.
- The app has no screen-reader support.

See [What the accessibility settings do and do not claim](/explanation/accessibility-limits/).

## Data control

| Row | Choices | Behaviour |
| --- | --- | --- |
| *Usage statistics* | *Off*, *On* | *Off* until pressed to *On*. The full list of what is sent is shown under the control, and the identifier is shown while on. Nothing is sent until it has been on for an hour. |

## Permissions

What the app may use on this computer. The page opens by saying that each of these is used only while something you started needs it, and that nothing it reads leaves this machine. It is not *Data control*, which is what leaves the machine: nothing on this page is sent.

Rows in page order. Each is *Ask*, *Allow* or *Deny* with your answer lit, and a line under it says what the lit answer means. A choice takes effect when pressed.

| Row | Used for | Default |
| --- | --- | --- |
| *Microphone* | Dictating in the editor | *Ask* |
| *Location* | Stories you play that change with where you are | *Ask* |
| *Date and time* | Stories you play that change with the time of day | *Allow* |

| Answer | Meaning |
| --- | --- |
| *Ask* | You are asked the first time something needs it. A story asks before it begins; see [The campaign window](/reference/campaign-window/#a-story-that-reads-the-time-or-the-location). |
| *Allow* | Used while something you started needs it, and never otherwise. |
| *Deny* | Never used, and nothing asks. |

The operating system has a say too, and is asked when the page opens or something needs the answer, and again whenever you come back to the app after that:

- Before the system has been asked, the row says so, and choosing *Allow* asks it once.
- When the system is why an *Allow* does not take, a line under the row says which: the system does not let the app use it, a policy on this computer does not, or there is nothing on the computer for the app to use.
- **Open system settings** appears on the row when the system has refused and has a setting to change it in. On macOS a change made there applies once the app restarts, and the page says so.

### Stand-ins

*Location* and *Date and time* each have a *Stand-in* field: what a story is told whenever it cannot have the real value, because you did not allow it or because this computer has nothing to give. A story cannot tell a stand-in from the real thing. The microphone has none; a story never reads it.

| Field | Accepts | Example |
| --- | --- | --- |
| *Date and time* | A date as year-month-day and a time on the 24-hour clock, with or without an offset from UTC. Without one, it is this computer's local time for that date. | `2026-10-19 18:30`, `2026-10-19T18:30+02:00` |
| *Location* | A place, by name or as a latitude and a longitude | `Rome, Italy`, `41.9028, 12.4964` |

- The field is checked as you type and kept as soon as it reads; there is no Apply. What does not read is said under the field and not kept.
- A line under the field says what stories will see: the moment with its offset, the place, or the latitude and longitude. The time is shown as typed, never converted to this computer's zone.
- Emptying the field removes the stand-in. With no stand-in for the date and time, a story that cannot have the real one is refused it.
- Allowed the location, a story is told where this computer is, to about the nearest town. The stand-in is used when you do not allow it, or when this computer cannot say.

How a script sees each answer is in [The world outside the story](/reference/python/the-world/#when-a-read-is-refused).

## Updates

### Release channel

Which releases the app offers you. **Stable** offers tested releases only. **Preview** also offers early builds of the next version, as soon as they are ready: their version ends in `-prev` and a number, such as 1.6.0-prev.2. A preview can change or break things before they reach Stable, and a project saved in one may be written in a newer format that Stable cannot open until it catches up.

| Control | Effect |
| --- | --- |
| *Release channel*: *Stable* | Only stable releases are offered. |
| *Release channel*: *Preview* | Previews are offered too. When a stable release is newer than the latest preview, that release is offered instead. Switching asks you to confirm first. |

After a switch the app checks again and says what it found under the control: a newer release, and that the download button at the top of the window installs it; nothing newer, so you stay where you are; or that the update server could not be reached. A version you install from the app is never older than the one you are running, on either channel. Switching back to Stable stops the previews; it does not reinstall an older version.

When you switch back to Stable while running a preview that is newer than Stable, the app warns you first and recommends staying on Preview. If you switch anyway, the preview you are running gets no updates until Stable passes it, and a project saved in the preview may not open in Stable.

A copy installed from a preview starts on Preview. The download page only ever offers Stable: Preview is reached from inside the app.

### Release notes

After an update the app shows what changed in each release you have not read yet, newest first. An update that skipped versions shows every one in between. Each release wears tags under its name: its size, and what it brings.

| Tag | Meaning |
| --- | --- |
| *Major*, *Minor*, *Patch* | The size of the release, read from its version number: 2.0.0, 1.5.0, 1.5.1. |
| *Hotfix* | A patch cut quickly to fix one problem. It takes the place of *Patch*. |
| *New features* | Something you could not do before. |
| *Improvements* | Something you could already do works better. |
| *Fixes* | Something that did not work now does. |
| *Action needed* | Something you have to do or know, such as a file older versions cannot open. |
| *Security* | A security problem is fixed. |

*Don't show release notes again*, at the bottom of the notice, turns it off. The notice says where to turn it back on.

| Control | Effect |
| --- | --- |
| *Release notes*: *Show after an update* | The notice appears after an update, for the releases the filters below let through. |
| *Release notes*: *Don't show* | No notice appears. *What's new*, on the About page, still lists every release. The filters stay on the page, greyed. |
| *Release type* | Which sizes of release are announced. |
| *Contents* | Which kinds of change are announced. |

A release is announced when its size is ticked **and** at least one of its contents is ticked. Unticking *Patch* hides every patch, whatever it fixes. With nothing ticked in a group, no release is announced. Releases you skip while the notice is off or filtered out are not shown later. A preview's notes are shown only to a preview, and wear a *Preview* tag; a stable release's notes cover every preview before it.

### Engine updates

The part of the app that plays and compiles campaigns can be fixed without a new installer. A fix is fetched in the background, checked against a signature before it is trusted, and used from the next launch. If the app crashes with a fix, the fix is set aside automatically. A fix never changes what the app can do.

A button in the app bar shows while a fix is arriving, and again once it is ready, with the version it moves to.

| Control | Effect |
| --- | --- |
| *Engine updates*: *On* | Fixes are fetched in the background and used from the next launch. |
| *Engine updates*: *Off* | The engine stays the one this version came with, or the last fix already fetched. |
| *Use the bundled engine* | Removes the fixes already fetched. The bundled engine is used from the next launch, and the page confirms it. |

While a fix is in use the page reads *Running engine* followed by its version, a fix fetched after this version was installed. The engine button opens a dialog with two states. While a fix downloads, it says the fix is being downloaded and checked and that nothing changes until the app next starts. When the fix is ready, it says it has been downloaded and checked, takes effect at the next start, and that there is nothing to install. What the request carries is in [What the app sends](/about/what-the-app-sends/).

### News

Short items from us, such as a new binding or integration, a change worth knowing about, or something to do before an update, shown on the home screen without an update. The **News** button on the home page's bar opens them as a screen of their own, newest first, each with a banner and its title. A number on the button counts the items you have not opened. Opening an item marks it and everything older as read, and *Mark all as read* does it for the lot. The first time, only items from the last thirty days count as unread.

| Control | Effect |
| --- | --- |
| *News*: *On* | Once per launch the app asks `ripplefx.app` for the news. The request carries nothing about you, and which items you have read stays on your machine. |
| *News*: *Off* | Nothing is fetched, and the News button is hidden. |

The news needs version 2.0 of the licence agreement. A copy that accepted 1.0 fetches nothing until it has accepted 2.0, whatever the switch says, and the page says so under it. If the news cannot be loaded, the screen says so and the next launch tries again. What the request carries is in [What the app sends](/about/what-the-app-sends/#news).

### Help menu

The rest of what you might attach, and the tips, are in the Help menu rather than on the page. All of them are also command palette commands.

| Entry | Does |
| --- | --- |
| *Show every tip again* | Each tip appears once more, as you reach the thing it is about |
| *Troubleshooting* ▸ *Copy package info* | Copies which build this is and how it was installed |
| *Troubleshooting* ▸ *Copy device info* | Copies the operating system underneath |

## First launch

After the agreement pages, a first launch shows three pages. All three can be skipped, and everything on them is in Settings afterwards.

| Page | Contents |
| --- | --- |
| First | Appearance, *Contrast*, *Colour vision* and how wires are drawn, beside a small preview of the app that changes as you choose |
| Second | *Write the way you like*: *Is most of your writing in English?*, with neither answer chosen. *Yes* offers two boxes, both ticked: *Check spelling and grammar*, and *Turn on dictation and download the English model*, which downloads once the first-launch pages are done, with the progress in Settings. *No* changes nothing. Added in 1.6, and shown only to a new installation. |
| Third | The *Usage statistics* question with neither answer chosen and the full list of what would be sent, how crash reports are asked, and a mention of donations |
