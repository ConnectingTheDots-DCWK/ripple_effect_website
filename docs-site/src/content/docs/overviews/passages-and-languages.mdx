A passage is Markdown. On a board it is a Narration node; on disk it is a
**localised passage** — a folder the app shows as one file, holding one `.md`
per language the project has.

<FileTree>
- chapters/
  - the_gates.graph.json
  - reaching_the_gates.loc.narr.bdl/
    - en-US.md the passage, in the language the story is written in
    - it-IT.md its translation
    - touch.json when each was last touched, so a clone can tell which is older
</FileTree>

One passage in several languages is one document — nothing anybody wants to
open separately. What is on disk stays ordinary Markdown, so a translator
handed the folder can work in any editor and a `git diff` reads as prose.

## Writing

Double-click a Narration node to write in it. The editor is the same Markdown
editor the app uses everywhere: a live render, a formatting toolbar, and image
embeds, local and remote, raster and SVG — drop a file on it and the link
writes itself. A picture picked from outside the project is copied into
`.ripple/external/` first, unless **Import outside assets** is switched off
in the File menu, in which case it is linked and Messages says so.

**The toolbar has an Image button beside Link**, in every Markdown editor — a
passage, a bundle, a document open in a tab. Type a few letters and it offers
the project's pictures, documents and sounds by name; for anything that is not
in the folder, give it a URL or a path. It writes `![alt](path)`, using
whatever you had selected as the alt text and otherwise leaving a prompt
selected for you to type over. Dragging a picture onto the editor still does
the same thing in one move, and writes the same thing into the file.

A link the app writes starts with a slash — `![map](/art/map.png)`, measured
from the project's root the way GitHub reads one — so a passage can be dragged
into a chapter and a folder renamed and the picture still points where it
did. A link written by hand without one goes on meaning what it always meant:
relative to the bundle's *parent* folder, the way a file in its place would
be, so `![](../art/map.png)` beside `chapters/the_gates.graph.json` means
`art/map.png`.

Two places in a passage can hold Python — an inline `{{ … }}` span and a
fenced ```` ```ripple ```` block — so a sentence can vary instead of forking
into two passages. A passage only *reads*; see [Python
scripting](/overviews/python-scripting/).

## Giving a passage things to read

A Narration node can be handed values. The **Reads** row sits at the bottom of
the card, beside the soundscape the node brings; it shows how many names the
passage is handed and opens the dialog where they are declared — a name and a
type each, written the way every other card's ports are. (It used to be an
*Edit what it reads…* entry on the right-click menu; it is not there any
more.) The card grows a port for each name, wire something in, and the
passage's Python reads it by that name: `You owe {{ gold }} crowns.` with a
number on the `gold` port. A slot with a default and nothing wired uses the
default.

The names belong to the **card**, not to the passage file, so one passage can
be read by two cards that fill it differently — a passage is a template. A
name the card does not hand over shows as a small warning where it stood, and
the rest of the passage renders as usual. Open a passage from a board and the
names it was given are offered as you type; open it in its own tab and they
are not, because there is no card to ask.

**A name has to be a name Python can read**: a letter or an underscore, then
letters, digits and underscores. A Python keyword such as `class` is refused,
with the reason shown under the field. A board written by an older version that
carries a name Python cannot read now reports it, as
[`W.GE.15`](/reference/diagnostics/), instead of silently never filling the
slot. The same rule holds for a Script node's inputs and outputs; an Output
node's rows and an Input node's fields are read by people, so `Your roll` is
still fine there.

## Choices

A Narration node's choices carry two limits besides their wording, and both
leave the choice on screen when they say no — greyed out and unpressable — so a
passage never quietly becomes an empty slide.

- **Times.** Open a choice and there is a *Times* box beside its name. Blank
  means as often as the reader likes; a number is how often one playthrough can
  take it. Once it is used up the choice stays on screen, greyed out. The card
  shows the ceiling as `×3` at the end of the choice's row.
- **A question.** Every wired choice has a small input on its row. Wire a
  `bool` into it and the choice is offered only while that is true. The two
  combine: *three times, and only while you carry the lantern* is one choice
  with both.

Put the cards that work the answer out **in the flow that leads to the
passage** — a Do-all with a chain on each branch and `completed` into the
passage is the tidy shape for several. A card hanging off the side of the board
is worked out once before the story starts and answers the same for ever; the
messages panel says so and names the choice (see
[Diagnostics](/reference/diagnostics/)). A Comparator reading a dice roll
follows the same rule. How the player shows a spent choice is under [Playing a
campaign](/overviews/playing-a-campaign/); the cards themselves are in
[Nodes](/reference/nodes/).

## The languages

**The language a story is written in is chosen when the project is made.** The
starting point comes from your computer's settings, but the choice is offered
rather than applied on your behalf. The languages it is *translated into* are
chosen in Project settings, which is a set of pages down a rail like the
app's own settings: *General*, *Languages* and *Narration roots* (and
*Capabilities*), each on its own. The languages are on the *Languages* page.

Switching a translation language on puts an empty translation into every
bundle. Switching one off deletes nothing: the files stay, the editor keeps
showing them marked retired, and readers stop being offered that language. If
you want the words gone, you are asked once, on save, and **Keep them** is the
button under your finger — nothing is deleted by clicking through the dialog
or dismissing it.

Project settings says what changing *Written in* will do, which is nothing to
your prose: every passage gets an empty file for the new language, everything
you have written stays where it is as a translation, and until you carry it
across your passages play empty. There is no migration for that yet.

## When a translation falls behind

The locale chips along the top of a bundle each stand for one language. A
**dot** on a chip means that translation is older than its source. The
Messages panel lists every one that has fallen behind, across the whole project.

The app cannot ask the filesystem this question — a `git clone` sets every
file's time to the moment of checkout — which is what `touch.json` is for. It
is written with sorted keys and UTC times so it stays quiet in a diff, and a
conflict between two translators is three lines a person can resolve.

## Reading time

Under every passage: the word count on the left, and on the right a choice of
reading pace — slow, average or fast — with the estimate beside it. It
keeps up as you type, and the pace you pick is remembered.

**It counts the language you are actually writing in.** Fifty-four of them,
each with its own reading speed, so a passage in German and the same passage
in English come out at about the same length of read even though the word
counts differ. Japanese, Chinese, Thai and Khmer are counted by the character,
because they are written without spaces between words and counting those by
the word gives an answer wrong by a factor of ten. A passage mixing scripts is
counted as both.

**The estimate says how much to trust it.** Seventeen of the languages carry
figures from reading studies; the rest are worked out from a close relative,
and the tooltip on the estimate says which one you are looking at.

Code does not count as prose: Python snippets and fenced blocks come out
before anything is counted, and a link is worth the words you read rather than
the length of its URL.

**A passage that mixes languages can be counted as one.** Off by default, and
switched on per project in settings: paragraphs written in a language other
than the passage's own are found and priced at that language's speed. It is a
project setting because whether your prose mixes languages is a fact about the
story, and it is off by default because it reads every paragraph after each
pause in typing. Short paragraphs are left alone — a language guessed from one
line is guessed, not known.

The arithmetic is a separate, open-source package:
[`dart_read_time`](https://github.com/ConnectingTheDots-DCWK/dart_read_time),
pure Dart, MIT.
